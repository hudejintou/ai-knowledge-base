### 前缀对比（5 查询 × 5 文档，本地 q8_0）

- Top1 命中：无前缀 3/5，有前缀 2/5 → 小语料下前缀无明显收益，差异在噪声范围。
- **核心发现**："怎么打包应用和依赖？" 与 Docker 文档近乎原文匹配，但两种模式下都只排第 4（~0.49-0.50）。结论：**nomic-embed-text-v1.5 以英文为主，中文语义排序能力弱**。

## 结论 / 学到的点

1. 最小 RAG 链路（Embedding → 余弦检索 → 引用问答 → 防幻觉）已完整跑通，阶段 0 目标达成。
2. Embedding 模型选择比前缀技巧重要得多；中文场景要用中文向模型。
3. 小语料下相关文档间语义污染明显（Celery 文档提到 Redis 导致缓存问题排序错乱）→ 主项目需要相关性阈值，必要时加 Reranker。

## 对主项目的决策影响

- 中文企业知识库 Embedding 选型：**bge-m3（GGUF，LM Studio 可跑）** 或 **智谱 embedding-3 API**，不再用 Nomic。
- 检索层设计：加相关性分数阈值（低于阈值直接拒答或走闲聊兜底）。
- 2026-12 的评估集（20-30 条）沿用本实验的"问题 + 正确文档"格式，可复用这 5 条做种子。
