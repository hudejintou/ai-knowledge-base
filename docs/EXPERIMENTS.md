  ## 实验 1：Qwen3-Embedding-0.6B 检索基线
- 语料：corpus.py，20 条 DOCS
- 评估：24 题（20 可回答 + 4 无关）
- 模型：text-embedding-qwen3-embedding-0.6b（LM Studio 本地）
- 前缀：不加
- top-1 命中率：100%，top-3：100%
- 可回答最低分：0.473（文档切多大比较合适？）
- 无关最高分：0.333（推荐一部好看的电影）
- 阈值：0.37（取分差区间内偏无关侧的值，余量较小）
- 拒答正确率：4/4
- 结论：当前语料和题目下分组可分；样本少，阈值需随语料扩充重测
## 实验 2：近邻无关题对阈值方案的影响
- 变更：EVAL_SET 新增 12 条"近邻但语料无答案"的题（Redis 集群、Celery 重试、Django 登录等）
- 结果：无关问题拒答正确率 4/16（原 4/4）
- 无关最高分 0.732（Function Calling 怎么做参数校验？），可回答最低分 0.473，分差 -0.259
- 结论：相似度衡量的是主题相似，不是答案是否存在。纯阈值方案无法区分"同主题但无答案"的问题。
- 决定：拒答改由回答模型判断可答性，用代码检测标记，并与阈值方案对比。
## 实验 3：模型判断可答性（[NO_ANSWER] 方案）
- 结果：无关拒答 16/16，可回答误拒 2/20，智谱调用 36 次
- 误拒原因分两类：
  - 模型过于保守：「怎么做接口的数据校验？」资料中有 Serializer 做数据校验的信息，但模型判定为不足
  - 语料不足：「文档切多大比较合适？」资料只说明过大过小的问题，没给具体大小，拒答有合理性
- 下一步：调整判断 Prompt，并补充语料

## 阶段 C 收尾结论（实验 12~19 汇总，2026-10-26）

- **检索参数 top_k**：严格 Prompt 下，top_k=2 与 top_k=3 均无误拒（RUNS=3 验证，实验 16），top_k=1 出现偶发误拒（3 次中 2 次，实验 14/16）。

- **默认候选**：块大小 400、重叠 50、top_k=3——**仅为候选值，未固定到代码默认参数**，待更大规模语料验证后再定稿。
- **适用范围**：结论只适用于本语料（24 段、48 题、单次运行、自定判定规则），不可外推。

## 实验 21：问答接口缓存（真实 Redis）耗时对比（阶段 D）
- 环境：Redis 8.10.3（本机 127.0.0.1:6379，brew services 启动）；Django runserver；单次请求，curl 计时
- 模型：glm-5.3-flash；缓存 TTL 3600s；问题："怎么做缓存？"
- 结果：
  - 未命中（首次，完整检索 + 生成）：200，6.53 s
  - 命中（同一进程内第二次）：200，0.0025 s
  - 重启 runserver 后命中：200，0.0078 s
  - 重启后 TTL：3208 s（写入约 392 s 后）
- 结论：真实 Redis 下缓存跨进程生效，命中耗时约为未命中的 1/800（约快三个数量级）。
- 注意：
  - 未命中耗时受智谱网络延迟影响，单次数据波动大（实验 20 为 3.1–4.9 s，本次为 6.5 s），不宜作精确指标。
  - 本次未重启 Redis 本身，缓存在 Redis 重启后是否保留取决于持久化配置，未验证。
  - 样本仅 1 个问题、单次请求，结论只能说明方向。
