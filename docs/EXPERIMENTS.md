  ## 实验 1：Qwen3-Embedding-0.6B 检索基线
- 语料：corpus.py，20 条 DOCS
- 评估：24 题（20 可回答 + 4 无关）
- 模型：text-embedding-qwen3-embedding-0.6b（LM Studio 本地）
- 前缀：不加
- top-1 命中率：100%，top-3：100%
- 可回答最低分：0.473（文档切多大比较合适？）
- 无关最高分：0.333（推荐一部好看的电影）
- 阈值：0.37（取分差区间内偏无关侧的值，余量较小）
- 拒答正确率：4/4
- 结论：当前语料和题目下分组可分；样本少，阈值需随语料扩充重测
## 实验 2：近邻无关题对阈值方案的影响
- 变更：EVAL_SET 新增 12 条"近邻但语料无答案"的题（Redis 集群、Celery 重试、Django 登录等）
- 结果：无关问题拒答正确率 4/16（原 4/4）
- 无关最高分 0.732（Function Calling 怎么做参数校验？），可回答最低分 0.473，分差 -0.259
- 结论：相似度衡量的是主题相似，不是答案是否存在。纯阈值方案无法区分"同主题但无答案"的问题。
- 决定：拒答改由回答模型判断可答性，用代码检测标记，并与阈值方案对比。
## 实验 3：模型判断可答性（[NO_ANSWER] 方案）
- 结果：无关拒答 16/16，可回答误拒 2/20，智谱调用 36 次
- 误拒原因分两类：
  - 模型过于保守：「怎么做接口的数据校验？」资料中有 Serializer 做数据校验的信息，但模型判定为不足
  - 语料不足：「文档切多大比较合适？」资料只说明过大过小的问题，没给具体大小，拒答有合理性
- 下一步：调整判断 Prompt，并补充语料

## 阶段 C 收尾结论（实验 12~19 汇总，2026-10-26）

- **检索参数 top_k**：严格 Prompt 下，top_k=2 与 top_k=3 均无误拒（RUNS=3 验证，实验 16），top_k=1 出现偶发误拒（3 次中 2 次，实验 14/16）。

- **默认候选**：块大小 400、重叠 50、top_k=3——**仅为候选值，未固定到代码默认参数**，待更大规模语料验证后再定稿。
- **适用范围**：结论只适用于本语料（24 段、48 题、单次运行、自定判定规则），不可外推。

## 实验 23：Celery 重试耗尽路径验证与补算（阶段 D，工程实验）
- 变量：入库时 LM Studio 不可用（连接失败），其余条件不变
- 配置：autoretry_for=(APIConnectionError, APITimeoutError, RateLimitError)，retry_backoff=True，retry_backoff_max=60，retry_jitter=True，max_retries=3
- 过程：
  - 关闭 LM Studio（/v1/models 无响应），提交文档 30，接口返回 202
  - worker 中同一 task id 共接收 4 次（首次 + 3 次重试），最终失败，错误为 APIConnectionError
  - 三次 Retry in 均为 0s：jitter 随机取值接近 0，未观察到指数退避
  - 每次 Celery 尝试内，openai SDK 另有 2 次内部重试
- 故障后状态：worker 失败后、补算前，执行 backfill_embeddings --dry-run 列出 [30]；同时 llen celery = 0，说明任务已被消费而非积压。即文档 30 为 embedding=NULL，直接观察到
- 补算：重启 LM Studio 后运行 backfill_embeddings，任务 0.69 秒完成，日志显示 文档 30 向量计算完成
- 补算后状态：dry-run 输出"没有需要补算向量的文档"；shell 检查 embedding is None 为 False
- 结论：
  - 连接类错误能被自动重试，重试耗尽后文档保留为空向量，补算命令可以找回并完成
  - 鉴权错误不在重试列表中，设计上直接失败，本次未验证
- 注意：
  - 样本为 1 条文档、1 次故障，不代表多故障并发的表现
  - jitter 使退避间隔不可观测，指数退避未经本次实验验证

## 实验 26：多跳与间接说法题集对比（阶段 E，容器内评估）
