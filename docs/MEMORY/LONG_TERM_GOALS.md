## 项目落地蓝图（纲领，定性描述）

### 主项目：企业知识库问答后端

- **主项目**：企业知识库 RAG 后端（Django/DRF + 本地 Embedding + 引用问答 + 工具调用 + Docker 部署）。
  - 深化方向：评估可信度（盲测）、检索质量，而不是无限加功能。

**最终形态**：一个可部署、可演示、可讲清楚取舍的知识库问答服务。能导入文档、检索、带引用回答、拒答，并有可复现的评估结果。

**分层方向**（按依赖顺序，不设固定日期）：

1. **数据层**：纯文本入库（已完成）→ PDF / Word 解析（计划中）。
2. **检索层**：向量检索（已完成）→ 切块策略固化（候选 400/50/3）→ 混合检索与重排序（待验证，只在评估证明有收益时做）。
3. **问答层**：工具模式与基线模式（已完成）→ 引用与拒答（已完成）→ 流式输出（可选）。
4. **工程层**：缓存、异步入库、错误分级、Docker（已完成）→ 鉴权、PostgreSQL、结构化日志（待补，面试时如实说明未做）。
5. **评估层**：固定题集（已完成）→ 盲测题集（计划中）→ 结果版本化与可复现（持续）。

**原则**：每新增一层，都要有对应的实验或测试，不做无法验证的功能。

### 小项目：轻量 Agent

- **小项目**：轻量 Agent（手写工具调用循环，不引入重框架）。
  - 与主项目的区别：主项目围绕"知识检索"，小项目围绕"通用工具编排与可靠性"。

**定位**：研究"通用工具编排"，与主项目互补。主项目围绕知识检索，小项目围绕工具注册、多步规划与错误恢复。

**能力路线**：工具注册与描述 → 多步循环与步数上限 → 工具失败时的恢复与报错 → 超时与可观测性（日志）→ 测试。

**反哺关系**：小项目里学到的步数上限、超时与错误恢复经验，回到主项目的 `agent.py` 中检验；主项目的评估方法，用于检验小项目的可靠性。

**边界**：不引入 LangChain 等重框架；不把小项目做成第二个 RAG 系统。

其他想法（AI Coding Assistant、本地助手、小程序 + AI 等）仅作储备，不并行立项。
