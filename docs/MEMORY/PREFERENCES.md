# PREFERENCES（偏好）

> 用途：怎么学习、怎么写代码、希望 AI 怎么配合。设备约束与模型选型是唯一记录处。

## 沟通方式

- ❌ 不说空话（"很强""非常厉害"之类）。
- ❌ 不一次给几十条命令，每次 1~3 条可直接执行的，并等待真实输出再继续。
- ❌ 不推荐 CUDA / Linux 专属方案，只给 Apple Silicon 方案。
- ❌ 不默认我精通 AI，也不当我是零基础。
- ✅ 客观分析：优缺点、成本、难点、可行性、学习收益、就业价值、是否值得投入。
- ✅ 我提出想法时帮判断：能不能做、我的电脑能不能跑、对简历有没有帮助、有没有更好的方式。
- ✅ 报错时等我贴完整终端输出，照着排查，不跳步。
- ✅ 讲原理简洁，代码优先，用 Python 和我当前的技术栈举例。
- ✅ 结论要带上适用前提（样本量、是否盲测、是否单次运行）。

## 学习偏好

- **AI 加速，不从头系统学**：按需补课，先做出东西，再回头讲原理。
- **一次只推进一个小步骤**，完成并验证后再进入下一步。
- 不做未经确认的扩展，不做没有决策价值的重复实验。
- 每完成一步，记录到 `docs/LOGS/` 或 `docs/EXPERIMENTS.md`，并提交 Git。

## 编程与项目偏好

- Python 为主，偏好可落地的工程方案，而不是 Demo。
- 项目要求：可运行、可部署、有 README、能放 GitHub。
- 代码风格：PEP 8，清晰分层（API / service / models / utils），注释说明"为什么"。
- 本地优先（LM Studio），其次云端 API。
- **Git 提交信息用中文**：写清背景、改了什么、为什么，回退或翻历史时无需看代码就能理解。
- 关于路线：主线只押 1 主 + 1 小；新方向先评估收益再决定是否投入。
