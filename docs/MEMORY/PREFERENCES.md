## 📚 学习偏好

### 学习方式
- **从实际项目入手**：先做出东西再解释原理。
- **一步一步操作**：给可直接复制执行的命令，不要一次给几十个未验证命令；默认每次只推进一个小步骤，必要时最多给 1-3 个命令。
- **控制额外动作**：尽量精简，避免用户未要求的扩展和重复整理。
- **先实践后理论**：遇到报错后根据真实终端输出继续排查，不喜欢脱离实际的纯理论堆砌。
- **原理解释**：保持简洁，但关键概念要讲清。

### AI 加速模式
- **核心原则**：尽可能使用 AI 辅助学习与开发，不从头系统学，快速上手、按需补课。
- **用 AI 做什么**：
  - 查漏补缺
  - 生成代码
  - 解释概念
  - 加速实战
  - Debug
  - 写文档
- **不用 AI 做什么**：
  - 基础语法（已会）
  - 核心原理（自己推，自己懂）

### AI 重点探索方向（按优先级排序）
1. **基础类**：LLM API 调用、Prompt Engineering、Function Calling
2. **实战类**：RAG、Agent、本地大模型部署
3. **应用类**：AI 应用开发、后端+AI 结合、AI 自动化工具
4. **进阶类**：向量数据库、模型推理与工程化、模型微调/量化/推理优化（条件具备时）
5. **副业类**：AI 编码工具、AI 自动化、AI 项目落地、AI 副业/接单/外包

## 🖥️ 环境适配偏好（M5 / 16GB）**

### 核心约束
- **设备**：MacBook Air M5，13 寸，16GB 统一内存，512GB SSD，Apple Silicon。
- **内存**：仅 16GB 统一内存（需特别重视）。
- **可用空间**：约 374GB（关注磁盘压力）。

### 适配原则
- **明确区分 Mac / Apple Silicon** 与 NVIDIA CUDA 的差异。
- **不把 Linux/NVIDIA 教程照搬**：不要推荐 CUDA、不要推荐需要大量显存的方案。
- **直接说明跑不动**：16GB 内存下跑不动的方案直接说明原因（模型大小、量化、内存压力）。

### 模型选择建议
| 模型 | 原始大小 | 建议量化 | 内存占用（近似） | 适用场景 | 推荐度 |
|------|---------|---------|-----------------|----------|--------|
| Qwen3.5 7B | ~4.7GB | 4-bit Q4_K_M | ~3-4GB | 日常对话、轻量任务 | ⭐⭐⭐⭐ |
| Qwen3.5 9B | ~7GB | 4-bit Q4_K_M | ~4.5-5GB | 编程、复杂任务 | ⭐⭐⭐⭐⭐ |
| Phi-3.5-mini | ~2.3GB | 4-bit Q4_K_M | ~1.5-2GB | 快速响应、多任务 | ⭐⭐⭐ |
| Qwen3-27B | ~21GB | - | **跑不动** | 不推荐 | ⚠️ |

### 推荐配置
- **日常辅助**：Qwen3.5 9B Q4_K_M（约 5GB）。
- **轻量任务**：Phi-3.5-mini Q4_K_M（约 2GB）。
- **双模型轮替**：根据任务动态切换模型（编程用 9B，简单对话用 mini）。

### 禁用方案
以下方案在 16GB 设备上**不建议尝试**，直接说明原因：
- Qwen3-27B（21GB+，跑不动）。
- Llama-3.1-70B（40GB+，跑不动）。
- 大模型量化（70B 即使 8-bit 也要 30GB+）。
- 需要大量显存的 GPU 方案（CUDA、H100 等）。

## 💬 沟通偏好

### 对我提出的想法
当你听到我说"我想学 XX"或"我想做 XX 项目"时，请帮我判断：

| 问题 | 期望回答 |
|------|---------|
| 能不能做？ | 技术可行性分析 |
| 我的电脑能不能做？ | 设备适配性分析（16GB 约束） |
| 学习成本？ | 预计学习时长、难度 |
| 对 AI 能力提升？ | 技能成长价值 |
| 对简历有帮助？ | 就业价值分析 |
| 能否变副业？ | 变现可行性 |
| 有没有更合适的方式？ | 替代方案建议 |

### 对推荐的技术/项目
期望得到客观分析：
- **优点**：清晰列出。
- **缺点**：清晰列出。
- **成本**：时间、金钱、算力。
- **技术难点**：有哪些坑。
- **实际可行性**：落地难度。
- **学习收益**：学会什么。
- **就业价值**：对找工作有帮助吗？
- **项目价值**：值得做项目吗？
- **是否值得投入时间**：综合判断。

### 对 AI 模型的推荐
- **不要**：只说"这个很好/很强"、"非常厉害"。
- **要**：
  - 性能数据（benchmark、速度、效果）。
  - 实际体验（流畅度、效果、稳定性）。
  - **我的设备能不能跑**（16GB 约束）。
  - 学习/部署成本。
  - 适用场景。

### 当我卡住/报错时
- **等我提供真实终端输出**。
- **根据我的报错继续排查**，不要跳过错误。
- **给出可执行的具体命令**，不要一次给一堆命令让我自己选。

### 原理讲解
- **保持简洁**：不要长篇大论。
- **关键概念要讲清**：核心思想、为什么这么做。
- **结合实际**：用我当前的技术栈举例。
- **代码优先**：先给代码，再解释代码背后的原理。

### 与我对话时
- **假设我知道**：Python、后端基础、计算机 408 基础。
- **不要假设**：不懂 AI、零基础。
- **用我的语言**：我懂 Python，用 Python 举例。
- **适配我的设备**：不要给 CUDA 方案，直接给 Apple Silicon 方案。
