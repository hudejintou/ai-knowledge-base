## 🧭 学习大纲

> 【必做】= 作品与面试硬通货；【选做】= 有余力再做。

### 阶段 A：RAG 可运行版（2026-10 下旬）【必做】✅
- [x] 回归测试：总体正确率 100%（46 题 × RUNS=3，实验 10）
- [x] 命令行问答入口 `rag/chat.py`
- [x] Git 提交与 README，首次推送 GitHub

### 阶段 B：后端化（2026-10 下旬 ~ 11 月上旬）【必做】✅
- [x] DRF `POST /api/ask/`：空问题 400，统一响应 `{"refused", "answer"}`
- [x] `Document` 模型：知识库从 `corpus.py` 迁入数据库，管理命令 `load_corpus`、`embed_documents`
- [x] 接口测试（可答 / 拒答 / 空问题），mock 模型调用
- [x] 配置集中到 `backend/qa/config.py`；Prompt 收敛为单一来源（`rag_v1.py` 从其导入）
- [x] 端到端回归（空问题 400 / 可答 200 / 拒答 200）

**验收标准**：① 接口返回带引用回答，拒答有明确语义 ✅；② 文档表增删改后无需改代码即可被检索 ✅；③ 测试覆盖可答、拒答、异常输入 ✅。

### 阶段 C：检索与切分实验（2026-10 下旬）【必做】✅
- [x] 检索参数：top_k=1/2/3 对照，RUNS=3 稳定性验证（实验 12–16）。结论：严格 Prompt 下 top_k=2/3 无误拒，top_k=1 偶发误拒。
- [x] 切分实验：块大小 200/400/800，单段题与跨段题（实验 17–19）。结论：400 的 top-1 最高，候选默认值为 400/50/3。

**验收标准**：① 检索类实验 ≥2 条（✅ 8 条）；② top_k 对照数据（✅）；③ 候选默认值 400/50/3 **仅为候选，未固定到代码**，结论只适用于当时的 24 段语料。

### 阶段 D：工程化（2026-10 下旬 ~ 10-31）【必做】✅
- [x] Redis 缓存：真实 Redis，TTL 1 小时，缓存完整结果（实验 20/21：命中毫秒级）
- [x] 日志与错误处理：502/503/500 分级，错误不缓存
- [x] Celery 异步入库：幂等、瞬时错误指数退避重试；接口 202 即返回（实验 22）
- [x] 重试耗尽与补算：`backfill_embeddings`（实验 23）
- [x] 入库后清空问答缓存；`GET /api/documents/<id>/` 状态查询
- [x] Docker Compose 一键启动（redis / web / worker，实验 24）

**验收标准**：① `docker compose up` 一条命令起全栈 ✅；② 缓存前后耗时对比 ✅；③ 入库走 Celery 不阻塞接口 ✅。

### 阶段 E：工具调用深化（2026-11-01）【主项目深化】✅
- [x] E1：验证 `glm-5.3-flash` 支持函数调用
- [x] E2：问答改为工具调用循环（最多 3 轮，每轮最多 2 次检索，超限强制作答），引用编号与 `sources`
- [x] 评估：工具版 vs 基线版（实验 25–27）。在 TOP_K=1 的多跳题上工具版覆盖率更高，但样本小、单次运行、题集非盲测
- [x] 扩充语料到 44 条，检索健康检查召回 11/12（实验 28）；回归 eval 两版均 100%
- [x] `QA_MODE` 开关，默认切换为工具模式（实验 29）

**验收标准**：① 两种模式可切换且接口已验证 ✅；② 结论写入 EXPERIMENTS.md ✅；③ 结论只作为"在当前小样本上的观察"，不作为"工具调用更优"的证明。

### 小项目：轻量 Agent（2026-11 中旬 ~ 12 月，并行进行）【必做】⬜
- 目标：不依赖 RAG 的通用 Agent 能力，与主项目形成互补，而不是重复。
- 学习重点：工具注册与描述、多步规划、错误恢复与超时、可观测性（日志/步数上限）。
- 产出：一个可运行的小型 Agent（复用 `test.py` 已有的工具调用循环），附测试与一页说明。
- 不引入 LangChain 等重框架，手写循环以便理解原理。

**验收标准**：① 至少 3 个工具，含一个会失败的工具，Agent 能恢复或正确报错；② 步数与超时有上限；③ 有测试覆盖循环逻辑；④ 有简短说明文档。

### 2026-12：补强【选做】
- 盲测题集：用新语料在不看结果的前提下设计题目，检验工具版是否稳定优于基线（实验 30+）。
- 候选默认值验证：扩大检索健康检查题数，决定是否固定 400/50/3。
- 流式输出（SSE）或文件上传解析（PDF/Word），二选一，视时间而定。
