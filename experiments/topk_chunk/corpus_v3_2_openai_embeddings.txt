嵌入（embedding）是把文本映射为浮点数向量的技术：一段文字经过嵌入模型编码后，会变成高维向量空间中的一个点。OpenAI 的 Embeddings 指南把嵌入定义为以浮点数列表表示的文本向量，其核心用途是度量文本之间的相关性——向量之间的距离被用来刻画语义关系，距离越近表示两段文本越相似，距离越远表示越不相关。这一"语义相近的文本拥有相近的向量"的假设，是相似度搜索、推荐、聚类、分类等一系列应用的基础。

衡量两个嵌入向量的距离有多种方式，指南推荐使用余弦相似度（cosine similarity）。它计算两个向量夹角的余弦值，取值范围从 -1 到 1，结果越接近 1 表示两段文本越相似，取值为 0 通常意味着不相关。由于余弦相似度只关注向量方向而不关注长度，它对文本长短的差异不敏感，因此成为文本检索中最常用的距离函数。在 RAG 系统里，用户查询会被编码成向量，再与知识库中所有文档向量逐一比较，返回最相近的若干段落作为上下文。

OpenAI 当前提供的第三代嵌入模型有两个。text-embedding-3-small 是性价比之选，输出维度为 1536，在 MTEB 基准上的得分为 62.3%，价格约为每百万输入 token 0.02 美元；与上一代 ada-002 相比，它性能更好而价格只有前者的五分之一左右。text-embedding-3-large 是能力上限之选，输出维度最高 3072，MTEB 得分约 64.6%，价格约为每百万 token 0.13 美元。两个模型的最大输入长度都是 8191 个 token，超长文本需要先切分再分别编码。

第三代嵌入模型采用 Matryoshka 表示学习技术训练，因此开发者可以通过 API 的 dimensions 参数主动缩短嵌入向量的长度，而基本不损失表征概念的能力。官方给出的对比是：把 text-embedding-3-large 截断到 256 维，其性能仍然超过未截断的 ada-002 的 1536 维向量。指南建议把维度调整放在检索管道的后续阶段进行，这样可以在存储成本与检索精度之间灵活权衡——先用完整维度建库，再按业务对延迟和成本的容忍度决定压缩比例。

指南列举了嵌入的典型应用场景：检索（按与查询的相关性对结果排序）、聚类（把语义相近的文本分组）、分类（按最相近的标签归类）、推荐（根据相关项目做推荐）、异常检测（识别与其他样本距离过远的离群点）以及多样性度量（分析文本相似度分布）。对于构建检索系统的开发者，指南展示了把嵌入向量存入向量数据库、再配合余弦相似度做语义搜索的完整流程，并提醒嵌入质量直接决定下游检索和生成效果的上限。

从工程角度看，使用嵌入的流程通常分两个阶段。索引阶段：调用 API 批量为文档生成向量，把向量与原文一起存入向量数据库或自建索引；查询阶段：把用户输入编码成同维度向量，通过最近邻搜索找出最相似的若干条记录。指南还提醒两点实践事项：单条文本超过 8191 token 时需要先切分再编码；查询与文档必须用同一个嵌入模型生成向量，不同模型甚至不同版本的向量空间互不兼容，混用会导致相似度失真。
